# 沉浸歌词工具栏过渡设计

## 背景与根因

主窗口通过 `ContentView` 的覆盖层展示 `ImmersiveView`。沉浸层在打开时从窗口底部向上滑入，在关闭时向下滑出。

当前打开流程会等沉浸层滑入动画结束后，才把原生 `NSToolbar` 设为不可见。因此顶部 Tab、通知和搜索框会一直停留在原位，最后瞬间消失。关闭流程则会在沉浸层开始滑出时恢复工具栏，工具栏随着遮罩退场逐步显露，形成了不对称的视觉效果。

## 目标

- 打开沉浸歌词时，顶部 Tab、通知和搜索框同步向上移动并淡出。
- 关闭沉浸歌词时，工具栏内容以相反方向恢复。
- 打开和关闭使用现有 `AnimationDuration.immersiveTransition` 时长。
- 保留现有的窗口布局稳定性，不在沉浸层尚未覆盖窗口时提前折叠原生工具栏。
- 经典工具栏和 macOS 26 新版工具栏保持一致。

## 方案

在 `ContentView` 中增加一个可复用的工具栏内容过渡修饰器，并应用到两套工具栏中的所有可见内容：

- `TabbedButtons`
- `NotificationTray`
- `SearchInputField`

当 `isImmersiveActive` 变为 `true` 时，修饰器使用与沉浸层相同的缓动和时长，把内容向上移出工具栏并将透明度降为零，同时禁用点击。打开动画完成后，继续沿用现有逻辑隐藏原生工具栏，避免工具栏结构提前折叠导致主内容跳动。

当 `isImmersiveActive` 变为 `false` 时，现有逻辑会在关闭动画开始时恢复原生工具栏。修饰器随后让工具栏内容从上方回到原位并恢复不透明度，与向下滑出的沉浸层形成反向过渡。

不采用立即隐藏 `NSToolbar` 的方案，因为它会在沉浸层尚未完全覆盖窗口时改变内容区高度。也不复制或截图工具栏，因为这会增加状态同步和跨 macOS 版本样式维护成本。

## 修改范围

- 修改 `Views/Main/ContentView.swift`，集中定义并应用工具栏内容过渡。
- 新增一个 `Scripts/test-immersive-toolbar-transition.sh` 定向回归检查。
- 不修改 `ImmersiveView` 的整体滑入、滑出 transition。
- 不修改工具栏按钮的功能、布局或本地化。

## 验证

1. 先运行新增定向检查，确认现有代码因缺少工具栏内容过渡而失败。
2. 实现修复后再次运行，确认经典和新版工具栏的可见内容都使用统一过渡。
3. 运行仓库中的全部 shell 检查。
4. 运行 Debug 构建，确认 SwiftUI 与 AppKit 交互可以编译。

人工验收时检查：打开沉浸歌词，顶部整组控件应与沉浸层同步向上消失；关闭时应自然恢复，且主内容区域不应出现跳动。
