# KSC 逐字歌词支持设计

## 背景

Petrichor 当前从音频文件旁读取同名 `.lrc` 和 `.srt` 歌词，也会在没有有效旁车歌词时读取数据库中的内嵌歌词。所有歌词入口最终使用 `LyricLine`：主窗口、迷你播放器和沉浸模式复用 `TrackLyricsContent`，桌面悬浮歌词通过 `DesktopLyricsLineProvider` 选择当前行和下一行。

KSC 是文本型卡拉 OK 歌词脚本。常见正文形态为 `karaoke.add('开始时间', '结束时间', '歌词文本', '逐字时长')`，其中逐字时长为逗号分隔的毫秒数。现有模型只能表达整行开始和结束时间，因此即使发现 `.ksc` 文件，也无法保留或渲染逐字进度。

## 目标

- 读取与音频文件同名的 `.ksc` 离线歌词旁车文件。
- 在主窗口、迷你播放器、沉浸模式和桌面悬浮歌词中显示 KSC 歌词。
- 按 KSC 提供的逐字持续时间，对当前歌词行进行从左向右的平滑扫色。
- 保持现有 LRC、SRT、内嵌歌词、缓存、自动滚动和桌面歌词状态行为不变。
- 继续在后台执行歌词文件读取，不新增运行时网络访问，也不写入歌词或音频文件。
- 删除曲目时，将同名 `.ksc` 作为歌词旁车文件一并移到废纸篓，并保留现有 fallback 行为。

## 非目标

- 不为 LRC、SRT 或内嵌纯文本合成逐字时间。
- 不编辑、转换或写回 KSC 文件。
- 不解析 KSC 的配色、歌手、字幕位置、脚本对象等控制指令。
- 不新增歌词设置、颜色设置或动画速度设置。
- 不新增数据库字段或迁移。

## 统一歌词模型

继续以 `LyricLine` 作为加载、缓存、行选择和显示的统一模型。为它增加可选的逐字时间片；每个时间片包含：

- 对应的文本片段；
- 相对于歌词行开始时间的开始偏移，单位为秒；
- 持续时间，单位为秒。

`LyricLine.text`、`startTime` 和 `endTime` 保持现有含义。LRC、SRT、内嵌歌词和无法取得可靠逐字时间的 KSC 行，其逐字时间片为空，因此现有消费者不需要改变行为。

KSC 文本按 Swift 扩展字素簇拆分，避免把 emoji、组合附加符号或其他用户感知字符拆开。逐字时长从零开始累加为相对偏移，不依赖渲染层重复计算。

## KSC 解析

新增 `LyricLine.parseKSC(from:)`，逐行识别大小写不敏感的 `karaoke.add(...)` 正文，忽略空行、注释、元数据和其他控制语句。解析范围如下：

- 接受常见的 `mm:ss.SSS` 与 `hh:mm:ss.SSS` 时间，也接受小时或分钟字段不补零的等价写法。
- 解析开始时间、结束时间、歌词文本和逗号分隔的逐字毫秒时长。
- 支持歌词参数中的标准反斜杠转义引号和反斜杠，使带撇号的歌词不会截断参数。
- 将有效行按开始时间稳定排序。
- 结束时间早于开始时间、时间无法解析或文本参数缺失时，跳过该行。
- 逐字时长缺失、包含非数字或负数、数量与文本扩展字素簇数量不一致时，保留该行的文本和行时间，但不附加逐字时间片。
- 零毫秒时间片允许存在，并在渲染时视为立即完成，避免合法文件因无声字符或占位字符被整体降级。

KSC 行自身的开始和结束时间是行级选择的权威边界。逐字时长总和不必与行持续时间完全相等；渲染进度以各时间片为准，并在行结束时保证整行完成高亮。

## 旁车发现与优先级

把旁车文件发现、编码探测和格式解析提取到一个只依赖 Foundation 的聚焦组件。`LyricsLoader` 继续通过现有 detached task 调用它，避免在主线程读取文件。

同名外部歌词按信息丰富度依次尝试：

1. `.ksc`
2. `.lrc`
3. `.srt`

只有成功解析出至少一行歌词的候选文件才会被选中。KSC 文件存在但无法解码或没有有效正文时，继续尝试 LRC、SRT 和内嵌歌词，而不是返回空结果。

复用现有编码集合，但针对 KSC 调整歧义编码的尝试顺序：先尝试 UTF-8 和带 BOM／具有明确零字节分布的 UTF-16，再优先尝试 GB18030、GBK，最后尝试 Shift JIS、EUC-JP、EUC-KR、Big5、ISO-2022-JP 及西文单字节 fallback。无 BOM 的 GBK 字节也可能被 UTF-16 或 Shift JIS 宽松解码，因此不能只凭“解码返回非空”把这些格式放在 GBK 前面。该策略无需新增依赖，并确保常见中文 KSC 不会显示为乱码。

`LyricsSource` 增加 `.ksc`，用于保留来源信息；缓存继续存放统一的 `LyricLine` 数组。

## 逐字进度和播放时间

新增纯计算辅助类型，负责：

- 根据绝对播放时间定位每个时间片是未开始、部分完成还是已完成；
- 将当前时间片映射为 `0...1` 的平滑填充比例；
- 对零时长、行开始前、行结束后和浮点边界进行钳制；
- 依据最近的播放进度样本和单调时钟计算插值播放时间。

现有播放进度在歌词可见时每 0.5 秒采样一次。为避免把整个应用的发布频率提升到 30 或 60 Hz，KSC 当前行在视图内部保存最近样本及其单调时钟锚点：播放期间以约 30 FPS 插值，暂停时保持样本时间，恢复、跳转、切歌或收到新样本时立即重设锚点。

只有当前 KSC 行需要逐帧更新。非当前歌词行、LRC/SRT 行和无有效逐字时间的 KSC 行保持静态，从而限制重绘范围。

## 渲染组件

新增共享的 `KaraokeLyricText` 组件，并由四个歌词入口共同使用。它先以未高亮颜色绘制完整文本，再以高亮颜色叠加已完成字符和当前字符的部分区域。当前字符在自身持续时间内从左向右平滑填充。

SwiftUI `Text` 无法在保留字形塑形、比例字体、组合字符、居中和换行的同时精确裁剪单个字形，因此该组件内部使用一个职责单一的 AppKit 文本绘制视图；外部接口仍是 SwiftUI。组件必须：

- 使用完整字符串进行排版，保持字体塑形、居中、换行及桌面歌词单行截断；
- 按扩展字素簇对应的字形范围裁剪当前字符的高亮绘制；
- 接收现有字体、字重、活动色、非活动色和行数限制；
- 暴露完整歌词文本作为辅助功能标签，不为每帧进度变化发布辅助功能通知。

主窗口、迷你播放器和沉浸模式继续保留当前行的粗体、缩放和自动居中滚动。当前 KSC 行改用 `KaraokeLyricText`；其他行继续使用普通 `Text`。桌面歌词的当前行使用相同逐字组件，下一行保持现有次要样式。

为了让桌面歌词取得逐字模型，当前/下一行显示值应携带 `LyricLine`，而不是只携带已剥离的字符串。行选择规则本身不变：当前行按行开始和结束时间选择，下一行跳过空文本。

## 降级和错误处理

- 单行逐字时间无效：显示文本并使用现有整行高亮。
- KSC 中部分正文行无效：跳过无效行，继续显示其他有效行。
- KSC 整体无有效行或无法读取：继续尝试 LRC、SRT 和内嵌歌词。
- 播放暂停：冻结逐字填充位置。
- 播放跳转或切歌：立即丢弃旧时间锚点和旧行进度。
- 插值超过当前行结束时间：钳制到行末，避免高亮越界。
- 字体或排版无法取得某个字形范围：该行安全降级为整行高亮，不影响歌词加载。

## 文件与沙盒行为

KSC 支持只读取用户已有的同名旁车文件，遵守当前 security-scoped URL 访问链路。应用不会修改 KSC 或音频文件。

`TrackTrashSidecars` 的歌词扩展名增加 `ksc`。当用户明确移动曲目到废纸篓时，同名 `.ksc` 与现有 `.lrc`、`.srt` 使用相同路径和卷级废纸篓 fallback；目录封面判定逻辑不变。

## 测试策略

采用测试先行的方式实现：

1. 扩展歌词解析脚本，覆盖标准 KSC 行、不同时间字段宽度、CRLF、行排序、转义引号、中文和 emoji 扩展字素、零时长、非法行以及字数/时长数量不匹配降级。
2. 为 Foundation-only 旁车组件增加真实临时文件检查，覆盖 `.ksc → .lrc → .srt` 优先级、无效 KSC 回退、GBK KSC 解码和来源类型。
3. 为纯逐字进度与播放时间锚点增加定向检查，覆盖行开始前、字符中点、字符边界、行末钳制、暂停、恢复和跳转重置。
4. 更新桌面歌词行选择检查，确认选择结果携带完整 `LyricLine`，并继续跳过空行。
5. 更新曲目废纸篓旁车检查，确认 `.ksc` 随同名音频移动且现有 fallback 保持不变。
6. 增加轻量结构性检查，确认主歌词内容和桌面歌词都接入共享逐字组件，并且没有把全局播放计时器提升为逐帧频率。
7. 运行所有歌词相关 shell 检查、`Scripts/test-track-trash-sidecars.sh` 和 Debug 构建。可行时再运行仓库全部 `Scripts/test-*.sh`。

## 兼容性与依赖

- 保持 Xcode 16、macOS 14+ 和当前 Swift/SwiftUI/AppKit 技术栈。
- 不新增第三方依赖。
- 不修改数据库 schema、普通播放列表文件行为或本地化资源。
- 不新增在线歌词、分析或后台数据收集。
