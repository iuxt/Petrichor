# 全屏播放控件尺寸调整设计

## 背景

全屏沉浸播放界面复用 `NowPlayingControlsView` 和 `NowPlayingProgressBar`。`ImmersiveView` 会根据窗口尺寸计算布局缩放，并把同一缩放值传给这两个紧凑型共享组件。

在常见的 1440×900 窗口尺寸下，沉浸布局的当前缩放值约为 0.85。因此播放键约为 36pt，上一首和下一首图标约为 14pt，进度轨高度约为 3.4pt。在全屏界面中，这些控件相对于封面和可用空间显得偏小。

## 目标

- 只放大全屏沉浸界面的播放控件。
- 将随机播放、上一首、播放/暂停、下一首和循环播放整排控件放大约 30%。
- 将进度轨、拖动圆点、时间文字和相关点击区域同步放大约 30%。
- 保持进度条整体宽度与封面宽度一致。
- 不改变迷你播放器和主窗口播放栏的尺寸或行为。
- 保留现有的响应式布局、颜色、悬停、禁用状态、播放和跳转行为。

## 方案

在 `ImmersiveLayout` 内集中调整 `controlsScale`，使其成为当前沉浸控件缩放值的 1.3 倍，并相应提高最大值。`ImmersiveView` 继续把这个缩放值同时传给 `NowPlayingControlsView` 和 `NowPlayingProgressBar`。

这种方式只改变沉浸界面的调用参数。共享组件本身及其默认缩放值保持不变，因此迷你播放器不会受到影响。按钮图标、按钮框、间距、阴影、进度轨、拖动圆点和时间标签仍使用组件现有的比例关系。

不修改共享组件的默认尺寸，因为那会同时放大迷你播放器。不为每个元素增加独立的沉浸尺寸参数，因为统一比例已经满足需求，额外参数会增加不必要的维护成本。

## 修改范围

- 修改 `Views/Immersive/ImmersiveView.swift` 中的沉浸控件缩放计算。
- 新增一个定向 shell 检查，约束 1.3 倍缩放、最大缩放值，以及两个共享控件继续使用同一沉浸缩放值。
- 不修改共享播放控件、播放逻辑、本地化资源或 Xcode 工程元数据。

## 验证

1. 先运行新增定向检查，确认当前代码因缺少 1.3 倍沉浸控件缩放而失败。
2. 实现调整后再次运行，确认定向检查通过。
3. 运行仓库中的全部 shell 检查。
4. 运行 Debug 构建，确认 SwiftUI 代码可以编译。

人工验收时，在全屏沉浸界面检查五个播放控件和进度控件均明显增大，布局仍居中且不重叠；迷你播放器和主窗口播放栏尺寸保持不变。
