# CUE 专辑与虚拟分轨

## 使用体验

把 `.cue` 和音频文件放在已授权的音乐目录，刷新资料库后即可在现有专辑界面浏览和播放。CUE 的全局 TITLE、PERFORMER 分别作为专辑名和专辑艺人；每个 AUDIO TRACK 展示独立曲名、艺人、曲序、时长。没有专辑名时以 CUE 文件名兜底，多艺人曲目仍归到同一专辑艺人下。

同一音频被有效 CUE 引用时，资料库只展示分轨，不再展示整轨副本。文件夹、搜索、队列、单曲循环、播放进度和恢复播放沿用现有行为。歌曲详情增加 CUE 文件路径和分轨区间。封面优先读取 CUE 专辑专属旁车，再从 CUE 所在目录及统一的代表音频解析；多文件 CUE 的各轨使用同一来源。

分轨不生成实体音频文件，也不修改 CUE 或音频文件。CUE 曲目信息编辑和单曲删除入口隐藏；如需修改，请编辑 CUE，或在访达中管理原文件后刷新。混合选择中包含 CUE 时，同样隐藏批量标签编辑、废纸篓操作。管理层也拒绝这些操作，避免从其他入口改写共享文件。

## 解析规则

- 支持单 FILE 整轨、多 FILE、引号内含空格的文件名、Windows 相对路径分隔符、大小写不敏感命令、CRLF、UTF-8/BOM、UTF-16 BOM 和常见旧式中文编码。无编码声明的旧式编码采用顺序探测，可能存在歧义。
- 支持全局及曲目 TITLE、PERFORMER、SONGWRITER，以及全局 REM DATE、GENRE、DISCNUMBER。
- INDEX 01 以 `mm:ss:ff`、每秒 75 帧换算。当前分轨结束于同一来源文件的下一条 INDEX 01；文件的最后一轨结束于真实音频 EOF。INDEX 00 的间隙保留在前一轨尾部；不合成 PREGAP/POSTGAP 静音。
- 只解析枚举到的已授权音频文件，不读取任意绝对路径或网络 URL。优先精确路径，其次大小写匹配，最后对 `.wav` 已转为 `.flac` / `.ape` 的旧 CUE 做唯一同名匹配。多个同名来源时不猜测。
- 缺少 INDEX 01、重复曲号、倒退时间、缺失来源、区间越界等，整张 CUE 不入库，来源音频继续按普通音频导入。多个 CUE 引用同一来源时按路径排序取首个有效文件，避免重复专辑。
- 首轨 INDEX 01 之前的隐藏音轨不作为单独曲目导入。本次不解析音频内嵌 CUE、BIN/CD 数据镜像。

解析规则参考：[GNU CUE sheet format](https://www.gnu.org/software/ccd2cue/manual/html_node/CUE-sheet-format.html)、[INDEX](https://www.gnu.org/software/ccd2cue/manual/html_node/INDEX-_0028CUE-Command_0029.html)。

## 存储、刷新与播放

`tracks.cue_segment` 保存 CUE 路径、真实音频路径、曲号、起止秒数和统一的代表音频路径（首个 FILE）。`tracks.path` 使用 `<cue 路径>#track-<曲号>` 作为唯一资料库身份，Track/FullTrack 的 `url` 始终指向真实音频。普通曲目保留原有路径。v19 迁移增加字段并使旧目录哈希失效，CUE 文件参与后续哈希计算。

同一 CUE 曲号重新扫描时保留数据库 ID、添加日期和播放历史。CUE 修改、删除、来源缺失会重新计算有效分轨并清理失效记录。书签目录迁移会同步更新 CUE 和音频路径。路径查询与文件夹计数使用真实音频位置；FTS 的原有排序链路保持不变。

文件型播放列表仍保存为 `.m3u`，每条 CUE 分轨写入上述虚拟身份的相对路径，Petrichor 可恢复到独立分轨；这是 Petrichor 内部约定，其他播放器通常无法识别该分轨路径。播放恢复同时保存数据库 ID 和虚拟路径。

播放使用 SFBAudioEngine 的 AudioRegionDecoder：先在后台打开真实音频，按实际解码采样率换算帧区间，再交给播放器。分轨有独立的时间零点、时长、seek 和 EOF。当前 Crescendo 公共接口只支持完整文件，因此 CUE 在两种引擎设置下均使用此区间解码路径，切换时保留音量、均衡器、前级和立体声设置。CUE 轨间沿用应用驱动的换曲，本次不保证无缝衔接。

## 歌词与封面

CUE 分轨支持现有的手动歌词搜索和 opt-in 自动歌词下载。每轨歌词存放于 CUE 同目录，以 `专辑.cue.track01.lrc` / `.ttml` 命名，曲名变化不改变保存位置。下载仍只发送匹配需要的歌曲信息；AMLL 保留原 TTML，其他来源保存 UTF-8 LRC，不写音频、CUE 或歌词数据库。

读取顺序为分轨专属旁车、整轨旁车、内嵌歌词。分轨旁车使用从零开始的单曲时间，不做二次减偏移；整轨歌词才按分轨区间裁剪、换算时间。逐字与对唱信息保留，跨分轨边界的歌词及词段被截取。当前区间没有内容时继续尝试下一种已有歌词格式或内嵌歌词，避免其他轨的 TTML 遮蔽当前轨的 LRC。自动下载只补当前轨，检查其所有旁车格式，保持默认关闭且不覆盖。

歌词加载结果携带实际来源文件 URL，重载、复制、语言切换、在访达显示、时间调整和删除均基于该来源。删除分轨专属歌词后自然回退到整轨歌词。调整或删除共享整轨歌词时，界面明确提示影响所有使用该文件的曲目；单曲音频移到废纸篓仍在 UI 和管理层禁用。异步下载按虚拟曲目身份区分，切歌会取消过期任务。

封面保存为 `专辑.cue.jpg`，优先于各音频文件的封面，原有文件不被改写。专辑网格、歌曲详情、播放列表、播放器和列表缩略图使用相同 CUE 路径及首个音频来源。自动下载沿用独立的封面 opt-in，按 CUE 专辑和来源去重，换轨不取消同专辑正在进行的下载；自动匹配还要求专辑一致。手动保存及替换提示影响整张专辑。完成后按 CUE 路径刷新视图和播放器，即使当前播放已换到另一个 FILE 也能更新。

## 验证

- `Scripts/test-cue-sheet.sh`：解析、编码、来源查找、时间戳、身份、M3U 和歌词区间。
- `Scripts/test-cue-library.sh`：实际 CUE 入库准备逻辑、元数据优先级、曲长、ID/历史保持、来源变更、冲突与多文件 CUE。
- `Scripts/test-cue-lyrics-loading.sh`：实际歌词加载器的来源优先级、两个时间基准、TTML、时间调整、删除后回退、内嵌歌词及跨界词段。
- `Scripts/test-cue-artwork-workflow.sh`：默认 opt-in、多文件专辑下载去重、换轨后刷新、手动覆盖及原文件保护。
- 歌词下载测试增加 CUE 自动/手动下载、跨格式防覆盖、原 TTML 保留和专属文件命名；封面存储和优先级测试增加 CUE 共享封面及符号链接保护。
- 队列/目录迁移、文件型播放列表、标签编辑、废纸篓、本地化与播放回归检查。
- `Scripts/test-cue-audio-decoder.sh`：复用 Debug 构建的 SFB 依赖，生成已知 PCM，验证实际区间解码的样本、EOF、75 帧换算和相对 seek；不打开音频输出设备。构建目录可通过 `PETRICHOR_DERIVED_DATA` 指定。
- macOS Debug 构建（本环境以 `CODE_SIGNING_ALLOWED=NO` 验证）。

本次验证：74 项 shell 检查通过（在线服务使用离线模拟测试）。`test-id3-selective-metadata-write.sh`、`test-track-metadata-embedded-content.sh` 因环境缺少 ffmpeg 未运行；新增 CUE 检查不依赖 ffmpeg，已通过实际 SFB PCM 解码及 Debug 构建验证。
