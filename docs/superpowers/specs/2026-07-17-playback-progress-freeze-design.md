# Modern Playback Progress Freeze Design

## Goal

修复现代媒体引擎开启时，手动播放曲目后偶发出现的显示时间冻结：声音正常、播放按钮显示为正在播放，但进度条停在 0，歌词也不前进；点击暂停后，显示时间立即恢复到真实位置。

修复必须保持离线，不修改用户的音频文件，也不改变现有播放、暂停、跳转、无缝播放和歌词加载行为。

## Root Cause

Petrichor 的 `PlaybackManager` 通过主队列定时器读取 `PlaybackEngine.currentPlaybackProgress`，再把结果发布到共享的 `PlaybackProgressState`。进度条和各歌词视图都依赖这个共享时间，因此它们会同时冻结。

现代媒体引擎当前固定在 CrescendoKit 1.0.0。手动替换正在播放的曲目时，Crescendo 偶发保持正常声音和 `.playing` 状态，但其 `currentTime` 查询暂时返回 0。暂停操作会建立稳定的内部时间锚点，此后查询立即返回真实位置。Petrichor 目前把每个引擎样本都直接视为权威值，也没有在“明确正在播放但引擎时间不增长”时提供显示时间回退，因此引擎的冻结值会直接冻结进度条和歌词。

现有的 `shouldPublishProgressSample` 防护解决的是经典 SFBAudioEngine 状态回调滞后问题：即使后端状态暂时不是 `.playing`，只要引擎时间在增长，仍发布进度。它不能处理本次相反的情况——播放状态正确，但引擎时间本身不增长。

## Chosen Approach

采用两层修复：

1. 将 CrescendoKit 从 1.0.0 升级到 1.1.1，取得上游针对播放位置和暂停启动路径的修复。
2. 在 Petrichor 的进度采样边界增加受限的单调时钟回退，使 UI 不再完全依赖单次引擎时间查询。

只升级依赖无法用仓库内的自动化测试稳定复现并锁定这次偶发问题。只增加应用层回退则会继续保留旧版引擎中已经修复的播放时间问题。两层处理既更新根因所在的引擎实现，也让应用面对暂时无效的时间样本时保持可用。

## Progress Resolution

新增一个不依赖具体播放引擎的纯进度解析单元。它接收：

- 引擎状态
- 当前引擎时间
- 上一个引擎时间
- 当前已发布的显示时间
- 距离上次采样的单调时钟间隔
- 用户最近的播放意图
- 当前曲目时长

解析规则如下：

1. 没有当前曲目，或引擎时间不是有限的非负数时，不发布样本。
2. 引擎时间正常增长时，以引擎时间为准，并退出回退状态。
3. 引擎或应用状态明确为播放时，第一次发现时间未增长只记录停滞，不立即合成时间。
4. 连续第二次发现引擎时间未增长，且最近的传输意图仍要求播放时，进入回退状态；使用单调时钟在当前显示时间基础上推进。
5. 回退期间如果引擎时间恢复增长，立即恢复引擎样本。为避免进度条向后抖动，播放期间的发布值保持单调不减；暂停后的真实样本可以校正显示时间。
6. 所有发布值限制在 `0...duration`；时长未知时只限制下界。

回退只影响用户可见的播放时间：

- 主播放器、迷你播放器和沉浸视图的进度
- 主歌词、迷你播放器歌词、沉浸歌词和桌面歌词
- Petrichor 维护的系统 Now Playing 时间

它不执行 seek，不改变播放队列，不改变引擎状态，也不作为曲目结束判定依据。

## Lifecycle and Reset Rules

进度解析状态由 `PlaybackManager` 在主 actor 上持有，与现有主队列采样器处于同一隔离域。

以下操作必须重置停滞计数、回退状态和单调时钟锚点：

- 开始手动播放新曲目
- 无缝切换到下一首
- 用户跳转播放位置
- 停止播放
- 恢复持久化的播放位置
- 重新加载媒体引擎
- 当前曲目被移动到废纸篓或恢复

暂停时停止单调推进，但保留最后显示时间。下一次采样优先接受暂停后引擎给出的稳定真实时间。恢复播放时从最近一次已发布时间重新建立单调锚点。

## Logging

当解析器首次进入回退状态时记录一次 warning，其中包含后端、引擎状态和冻结时间。引擎时间恢复后记录一次 info。

一次停滞期间不重复刷日志。切歌、跳转或其他重置会开始新的诊断周期。

## Dependency Update

将 `Petrichor.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved` 中的 CrescendoKit pin 从 1.0.0 更新到 1.1.1。项目声明已经使用兼容的 `upToNextMajorVersion` 规则，不需要修改 Xcode project 元数据。

升级后检查 Crescendo、CFFmpeg 和 CTagLib 三个二进制依赖均由 SwiftPM 解析到 1.1.1 发布所声明的校验产物。

## Testing

先增加失败的定向回归检查，再修改生产代码。纯进度解析覆盖：

- 正常增长的引擎时间直接发布
- 第一个冻结样本不立即外推
- 连续冻结样本在播放意图有效时按单调时间推进
- 引擎时间恢复后退出回退
- 暂停时停止外推并接受稳定真实时间
- 显式暂停意图禁止回退
- 曲目时长钳制
- 切歌和 seek 后重置，旧曲目的停滞状态不泄漏

现有 `Scripts/test-playback-progress-state-race.sh` 继续覆盖经典引擎的状态回调竞态。新增检查覆盖现代引擎时间冻结，两者职责保持分离。

验证顺序：

1. 运行新增回归检查并确认在生产代码修改前按预期失败。
2. 实施最小进度解析和生命周期重置。
3. 重新运行新增检查以及现有播放进度、播放按钮和歌词时间检查。
4. 运行仓库全部 `Scripts/test-*.sh`。
5. 运行 Debug `xcodebuild`，确认 CrescendoKit 1.1.1 解析并且应用成功构建。

## Acceptance Criteria

- 现代媒体引擎播放中即使连续返回 0，进度条最多停留一个采样周期，随后继续前进。
- 所有同步歌词使用同一个恢复后的共享时间继续更新。
- 点击暂停后进度停在真实位置，不继续外推。
- seek、切歌、恢复播放和无缝切换不会继承旧的停滞状态。
- 经典媒体引擎行为保持不变。
- 不写入音频文件，不增加联网音乐服务，也不改变资料库和播放列表存储。
